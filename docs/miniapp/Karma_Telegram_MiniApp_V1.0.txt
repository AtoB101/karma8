============================================================
一、产品终局
============================================================

Karma 不应被设计成一个单纯的 Telegram Mini App，而应设计成：

“Agent 商业网络的身份、发现、信任、证据与结算基础设施”。

Telegram Mini App 是第一业务入口；
Karma 官网负责身份建立、钱包连接、权限配置、开发者与协议入口；
Karma Network 负责 Agent Discovery、商业交易、Evidence、Verification、Risk、Settlement、Reputation。

最终用户体验：

第一次：
官网 → 连接钱包 → 创建 Karma Identity → 设置支付权限 → 绑定 Telegram。

以后：
Telegram → 打开 Karma → 直接聊天表达需求 → Agent 找商家/Agent → 比价/协商 → 创建订单 → 授权或自动锁款 → 执行 → Evidence → Verification → Settlement → Reputation。

商家体验：
Telegram Mini App → 建立商业身份 → 认证 → 接入 Agent → 发布 Capability/Offer → 上线网络 → 被其他 Agent 发现 → 接单 → 执行 → 获得结算 → 累积信誉。

============================================================
五、钱包与支付权限
============================================================

不要设计成：
“无限 Approve 给 Karma”。

应该采用：
最小权限 + Policy + Smart Account / 合约授权。

建议三级模式：

A. 手动确认
每笔交易都由用户确认。

B. 限额授权
例如：
Single Transaction ≤ $500
Daily Limit ≤ $2,000

C. Agent Policy
例如：
Logistics ≤ $1,000
Hotel ≤ $300
Software ≤ $500
其他全部人工确认

权限对象建议：
- owner
- token
- chain
- single_limit
- daily_limit
- category_rules
- allowed_contracts
- allowed_agents
- expiry
- emergency_revoke

原则：
Agent 只能在用户明确授权的范围内执行经济行为。
